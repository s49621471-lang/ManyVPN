# ManyVPN

Автоматически собираемая и **реально проверяемая** VPN‑подписка с большим количеством стран.
Ориентирована на Россию и другие страны с ограничениями доступа в интернет.

Подписка совместима с Happ, v2rayNG, Hiddify, NekoBox, Streisand, Shadowrocket, Karing,
sing-box, Clash / Mihomo и другими клиентами.

```

```

Остальные форматы:

с таблицей стран и временем последнего обновления.

## Как выглядит подписка

```
⚡ Авто выбор
🇩🇪 Германия 1
🇩🇪 Германия 2
🇳🇱 Нидерланды 1
🇳🇱 Нидерланды 2
🇳🇱 Нидерланды 3
🇫🇮 Финляндия
...
⚡ Авто выбор 🏳️
🇳🇱 Нидерланды 🏳️ 1
🇩🇪 Германия 🏳️ 1
...
```

* Первым пунктом идёт **⚡ Авто выбор** — самый быстрый сервер по результатам последней проверки.
  В форматах sing-box и Clash это настоящая группа `urltest` / `url-test`: клиент сам продолжает
  замерять задержку и переключается на самый быстрый сервер.
* Дальше — обычные серверы, сгруппированные по странам, максимум **3 сервера на страну**.
* Внизу — серверы для **обхода белых списков** (когда провайдер пропускает только разрешённые
  ресурсы). Они помечены флагом `🏳️` и имеют собственный авто‑выбор **⚡ Авто выбор 🏳️**.

## Что именно проверяется

Сборка не доверяет названиям конфигов. Каждый кандидат проходит две ступени:

1. **TCP‑проверка** — соединение с `host:port` с таймаутом, отсеивает мёртвые адреса.
2. **Реальная проверка через прокси** — поднимаются ядра `sing-box` и `Xray` с отдельным
   локальным входом на каждый сервер, через сервер выполняется HTTPS‑запрос к
   `cp.cloudflare.com/cdn-cgi/trace` (запасной вариант — `ip-api.com`). Из ответа берутся:
   * **страна реального выхода** — по IP, с которого запрос пришёл на сервис, а не по названию;
   * **задержка** — по времени полного запроса через туннель, лучшее из нескольких попыток;
   * **выходной IP** — по нему серверы внутри одной страны разводятся по разным выходам.

Сервер попадает в подписку, только если запрос через него действительно дошёл и страна определена.

## Правила отбора

| Правило | Значение |
| --- | --- |
| Максимум серверов на страну | 3 (берутся самые быстрые) |
| Если серверов меньше трёх | остаётся столько, сколько есть |
| Если ни один сервер страны не прошёл проверку | страна не добавляется |
| Всего серверов в подписке | до 300 |
| Порог задержки | 3500 мс |
| Дублей на один `host:port` | не более 4 кандидатов |
| Серверы с одинаковым выходным IP | не более двух на страну |

Учитывается история: для каждого сервера хранится оценка стабильности (экспоненциальное
сглаживание успехов прошлых прогонов). При равной скорости выигрывает сервер, который стабильно
работал раньше. История лежит в `sub/history.json` и переносится между запусками.

## Обновление

GitHub Actions (`.github/workflows/update.yml`) запускает сборку **каждые 4 часа**, а также
по кнопке *Run workflow* и при изменении кода или списка источников. Результат публикуется
принудительным пушем в ветку `sub` — одна ревизия, репозиторий не разрастается.

> Расписание `schedule` в GitHub Actions работает только для ветки по умолчанию репозитория.
> Сейчас это `claude/manyvpn-subscription-uegnwi`, поэтому обновление по расписанию уже работает.
> Если переключите ветку по умолчанию, перенесите туда и код, иначе останутся только ручные запуски.

## Источники

Список в [`sources.json`](sources.json) — 79 регулярно обновляемых подписок с GitHub
(агрегаторы Telegram‑каналов, коллекции VLESS/Reality, наборы для России, сборники Clash).
Формат записи:

```json
{ "label": "название", "url": "https://raw.githubusercontent.com/...", "whitelist": false, "enabled": true }
```

* `whitelist: true` — весь источник помечается как «обход белых списков».
* `enabled: false` — источник временно отключается.

Недоступный источник не ломает сборку: он пропускается, а причина попадает в лог и `status.json`.
Помимо флага источника, признак белых списков определяется по SNI и заголовку `Host` — если
маскировка идёт под российский разрешённый домен (`vk.com`, `mail.ru`, `gosuslugi.ru`, `yandex.ru`
и ещё несколько десятков), сервер уходит в нижнюю группу.

## Поддерживаемые протоколы

`VLESS` (в том числе Reality и XTLS Vision), `VMess`, `Trojan`, `Shadowsocks`, `Hysteria2`, `TUIC`.
Транспорты: `tcp`, `ws`, `grpc`, `http`, `httpupgrade`, `xhttp`.

`XHTTP` проверяется и выдаётся только через Xray‑совместимые форматы (base64 и список URI),
потому что sing-box и Mihomo этот транспорт не поддерживают. По той же причине в файлах
sing-box и Clash серверов может быть немного меньше, чем в base64‑подписке.

## Настройка

[`config.json`](config.json):

| Параметр | Смысл |
| --- | --- |
| `max_per_country` | сколько серверов оставлять на страну |
| `max_total` | предел общего количества серверов |
| `whitelist_share` | доля мест под серверы обхода белых списков |
| `country_order` | `latency` — страны по скорости, `alpha` — по алфавиту |
| `max_verify` | сколько кандидатов отправлять на глубокую проверку |
| `latency_max_ms` | порог задержки |
| `exclude_countries` | коды стран, которые не нужны, например `["RU"]` |

## Локальный запуск

```bash
pip install -r requirements.txt
python -m manyvpn \
  --output sub \
  --history state/history.json \
  --singbox /путь/к/sing-box \
  --xray /путь/к/xray
```

Полезные флаги: `--max-verify N`, `--max-total N`, `--limit-sources N`, `--skip-tcp`.

Для проверки нужны прямые исходящие TCP‑соединения на произвольные порты. В окружениях,
где весь трафик идёт через HTTP‑прокси, проверка не проходит и подписка не перезаписывается —
это защита от публикации пустого результата.
